- **Live task board — Textual TUI (TODO §1, commit `f10b6d8`).** Replaced the v0 static text dump with a full-screen Textual app that re-renders on every filesystem change under `runs/`. Architecture: pure `lib/board/source.py` (readers from `metadata.yaml` + tail of `events.jsonl`) → frozen `BoardSnapshot` (`lib/board/snapshot.py`) → Textual app (`lib/board/app.py`) driven by a `watchdog` Observer + 1Hz fallback `set_interval`. The fallback timer keeps the age tickers moving and rescues us on filesystems without inotify-equivalent events. `textual` + `watchdog` are gated behind a `[board]` optional-deps group (`requirements-board.txt`); the core CLI stays stdlib-only as before. `--static` preserves the v0 one-shot text contract for CI / headless. 17 new unit tests against the snapshot builder; the legacy `test_cmd_board.py` retargeted at the static fallback. Smoke-tested in-process with `app.run_test()`: dropping a run on disk while the app was mounted fired the watchdog and the new card appeared in the right column without keyboard input.

- **Live board UX polish (TODO §1, current pass).** Restructured the card from a single dim Rich blob into five labelled bands joined by `─` rules: title (slug bright + `YYYY-MM-DD-` dimmed-out + state badge + scope + `● live`), meta (age-in-stage · age since update · total · repo · branch, dim), body (status-aware progress, with the severity reason as the first body line), events (`[mm:ss ago] EventType detail` with a fixed-width 11-char timestamp column), and an opt-in files band labelled `run` / `wt` with `$HOME → ~` and the workbench root → `…`. Default contrast inverted: body band uses the default brightness, meta + files bands keep `dim`. Files band is OFF by default — most board sessions watch state, not paths — and `--verbose` opts in. Loudness graded: warning (`⚠`, yellow border) for `has_known_issues` / `has_recent_error` / `worktree_missing`; blocking (`✕`, red border) for `failing_tests` / `builder_gave_up` / `is_stale_human_review`. Each level surfaces a one-line reason in the body band (`✕ tests failing`, `⚠ 2 known issues`) so the loudness is self-explaining. Per-column subtitle string pulled from a new `COLUMN_SUBTITLES` constant in `lib/board/source.py`. Twenty-four new tests across `TestSeverityClassification`, `TestPathAbbreviation`, `TestStaticCardBands`, `TestStaticHeaderSubtitle`, and `TestStaticVerbosePaths` exercise the new branches; one existing test that asserted the legacy `! r-stale` marker was updated to the new `✕ r-stale` form (stale `human_review` is now a blocking-severity flag). 164 → 188 tests green.

- **Audit unit tests for duplication (TODO §3, commit `<PENDING>`; run `2026-05-22-audit-unit-tests-for-duplication`).** The suite had grown to 193 tests across 14 modules, with several near-duplicates seeded by feature work that each added its own test class. Walked every module, identified ten that contained methods sharing preconditions, and folded them — each fold collapses N methods into one method whose body is a `for label, … in cases:` loop with `msg=label` on each `assert*` call so failure diagnosis still names the row. Suite shrunk **193 → 134 (−59 tests, −30.6%)**, green twice in a row. Biggest reductions: `test_scope_check.py` 16 → 2 (`TestExtractExpectedFiles` 6→1, `TestDetectCreep` 10→1), `test_cmd_board.py` 35 → 22 (`TestSeverityClassification` 8→1, `TestPathAbbreviation` 4→1, three severity-marker tests in `TestStaticCardBands` 3→1), `test_doc_claims.py` 10 → 2 (`TestExtract` 6→1 with a `(op, value)` dispatch for the `NONE_NEEDED` sentinel, `TestVerify` 4→1), `test_followups.py` 12 → 6, `test_run_ids.py` 12 → 6, `test_board_snapshot.py` 39 → 34 (`TestLiveSignal` 3→1, `TestAcceptanceCoverage` 3→1, `TestWorktreeMissingFlag` 2→1), `test_lifecycle.py` 18 → 15 (`TestHumanReviewValidation` 4→1). Four modules walked but left untouched: `test_transitions.py`, `test_integration.py`, `test_cmd_plan_parser.py`, `test_e2e.py` — each one's tests cover distinct preconditions/branches and folding would inflate the body without lowering the count. **The plan got the mechanism wrong on the first pass:** it called for `pytest.mark.parametrize` as the merge mechanism, but pytest counts each parametrize case as a test ID, so parametrize alone doesn't reduce the count.
